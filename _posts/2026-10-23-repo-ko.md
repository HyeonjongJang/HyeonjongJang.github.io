*ESP32-S3 보드 하나로 비전-언어 모델에게 실제 iPhone의 눈과 손을 줍니다: 런타임에 Mac 불필요, 탈옥 불필요, 개발자 계정 불필요.*

## 이게 뭔가요

ESP32 iPhone Agent는 약 $7짜리 ESP32-S3 마이크로컨트롤러를 비전 AI 모델과 실제 iPhone 사이의 다리로 바꿔주는 오픈소스 프로젝트입니다. 보드를 iPhone의 USB-C 포트에 꽂으면 두 가지 일을 합니다: AirPlay 수신기 역할을 해서 모델이 화면을 볼 수 있게 하고, USB HID 마우스/키보드 역할을 해서 모델이 탭, 스와이프, 타이핑을 할 수 있게 합니다. 같은 iPhone에서 동작하는 iOS 앱이 미러링된 영상을 디코딩하고, 스크린샷을 OpenAI 호환 비전 엔드포인트에 보내고, 모델의 판단을 보드를 통해 HID 명령으로 변환합니다.

대상 사용자는 실제 휴대폰 인터페이스와 상호작용하는 AI 에이전트를 실험하는 개발자입니다: iOS에 적용한 "computer use" 패턴으로, 런타임에 Mac 연결, 탈옥, 유료 개발자 계정이 필요 없습니다 (무료 Apple ID로 앱 서명 가능, 7일마다 재서명 필요). iOS 18 이상이 필요합니다.

## 동작 원리

시스템은 세 부분(눈, 손, 두뇌)이 루프로 연결되어 있습니다.

**눈: 보드로의 AirPlay 미러링.** ESP32-S3가 자체 Wi-Fi 핫스팟을 만들고, iPhone의 화면 미러링 메뉴에 "ESP32 Agent"라는 AirPlay 수신기로 나타납니다. iPhone이 미러링을 시작하면 보드가 H.264 비디오 스트림을 받습니다. 보드 자체에서 디코딩하지는 않고, 압축된 스트림을 BLE를 통해 같은 iPhone에서 실행 중인 iOS 앱으로 전달합니다. iPhone은 보드의 핫스팟에 Wi-Fi가 연결된 동안에도 셀룰러 데이터로 인터넷에 접속합니다.

**손: USB HID.** iPhone의 USB-C 포트에 물리적으로 연결된 보드는 표준 USB 마우스와 키보드로 인식됩니다. iOS의 AssistiveTouch를 켜면 마우스가 화면 위의 포인터를 제어합니다: 클릭이 탭이 되고, 드래그가 스와이프가 되고, 키보드 이벤트가 텍스트 입력(현재 ASCII만)이 됩니다.

**두뇌: iOS 앱.** 앱이 H.264 스트림을 디코딩하고, 스크린샷을 캡처하고, 사용자가 설정한 OpenAI 호환 비전 모델 엔드포인트로 보냅니다. 플래너(planner)–액터(actor) 루프를 실행합니다: 플래너가 다음 행동을 결정하고, 액터가 실행합니다: 탭, 스와이프, 그리기, 타이핑, 키 누르기, 홈 이동, 또는 완료. 작업 중에 앱은 백그라운드로 전환되고 Dynamic Island를 통해 진행 상황을 보여줍니다.

**루프 완성: 포인터 추적과 보정.** USB HID 포인터는 상대 좌표를 사용하기 때문에, 앱은 포인터가 실제로 어디 있는지 알아야 합니다. README에 설명된 보정 메커니즘은 이렇습니다: 정밀한 탭 전에 앱이 포인터를 흔들고, 미러링된 스크린샷에서 포인터를 찾아서, 오차를 보정합니다. 각 행동 후에는 화면이 안정될 때까지 기다리고, 모델에게 변화가 있었는지 알려줍니다. 보드, 핫스팟, 미러링 연결이 끊기면 실행이 일시정지되고 같은 단계에서 재개됩니다.

잠긴 방 바깥에 원격 조종 카메라와 로봇 팔을 붙여 놓은 것과 비슷합니다 (제 비유이지 프로젝트의 설명이 아닙니다). 카메라가 창문을 통해 안을 들여다보고 (AirPlay 미러), 팔이 문틈으로 손을 넣고 (USB HID), 다른 건물에 있는 사람이 카메라 피드를 보면서 팔에 지시를 내립니다. 방 자체(iOS)는 건드리지 않습니다: 탈옥도, 디버그 훅도, 표준 AssistiveTouch 외의 접근성(accessibility) API도 사용하지 않습니다.

**리뷰와 내보내기.** 모든 실행 기록이 iPhone에 저장되며, 탭과 스와이프가 표시된 상태로 단계별 재생할 수 있습니다. 스크린샷, 행동, 주석을 앱에서 내보내서 분석할 수 있습니다.

## 사용 방법

README에서 설명하는 설정은 세 단계입니다: 보드 플래시, 앱 빌드, 설정.

**보드 플래시** (Mac에 보드를 USB로 연결한 상태에서):

arduino-cli lib install "NimBLE-Arduino@2.5.1"
hardware/flash.sh            # 선택: [시리얼 포트] [--debug]

README에 따르면 [arduino-cli](https://arduino.github.io/arduino-cli/), ESP32 코어 3.3.x, NimBLE-Arduino 2.5.x가 필요합니다. `flash.sh`로 빌드해야 하는 이유는 이 스크립트가 `hardware/hid_bridge/nimble_cfg.h`에 정의된 BLE 버퍼 크기를 적용하기 때문입니다.

**iOS 앱 빌드 및 설치** (Mac에서 Xcode 필요):

cp ios/Config/Local.xcconfig.example ios/Config/Local.xcconfig   # DEVELOPMENT_TEAM과 IA_BUNDLE_ID 설정
open ios/IPhoneAgent.xcodeproj                                    # IPhoneAgent 스킴을 iPhone에서 실행

Xcode 프로젝트는 `ios/project.yml`로부터 XcodeGen으로 생성됩니다. 무료 Apple ID로 서명할 수 있지만, 7일마다 재서명이 필요합니다. 원탭 핫스팟 연결 기능은 유료 Apple 개발자 계정이 필요하며, 없으면 앱이 핫스팟 비밀번호를 보여줘서 수동으로 연결하게 합니다.

**앱 내 초기 설정**은 네 단계를 안내합니다: Bluetooth로 보드 페어링, 보드 Wi-Fi 연결 후 화면 미러링 시작, AssistiveTouch 켜고 포인터 보정, 모델 엔드포인트와 API 키 입력.

**작업 실행:** 목표를 입력하고 (README의 예시: *"Open Settings and go to Wi-Fi"*) Start를 누릅니다. Siri, 단축어, 위젯, 제어 센터를 통해 저장된 작업을 실행할 수도 있습니다.

이 프로젝트를 직접 빌드하거나 실행하지는 않았습니다: 위 단계는 전부 README에서 가져온 것입니다. Mac은 최초 플래시와 앱 빌드에만 필요하고, 런타임에는 iPhone과 보드만 있으면 됩니다.

## 주목할 만한 세부사항

**모델 유연성.** 앱은 어떤 OpenAI 호환 비전 엔드포인트와도 동작합니다: README에 vLLM, SGLang, llama.cpp, Ollama, 클라우드 API가 나열되어 있습니다. 플래너와 액터에 각각 다른 모델을 설정할 수 있습니다. 앱이 엔드포인트의 모델 목록을 조회해서 선택하게 해줍니다. 개발에는 nvidia/Qwen3.8-Flash-Next-NVFP4를 두 대의 DGX Spark에서 서빙하여 사용했습니다.

**대역폭 제약.** README에 따르면 BLE는 약 300–500 kbps를 전달하므로, 미러링 화면은 480×1040 해상도에 최대 5 fps입니다. 각 단계는 수 초가 걸리며, 대부분 모델 추론(inference) 시간입니다.

**iOS 미러링 제한.** iOS는 특정 화면(암호 입력, Apple Pay, DRM 보호 영상)을 미러링하지 않으므로, 에이전트가 이런 화면을 보거나 조작할 수 없습니다. 화면이 잠기면 미러링이 중단됩니다.

**연결 트레이드오프.** 에이전트 실행 중 iPhone의 Wi-Fi는 보드 핫스팟에 점유되어 Wi-Fi 인터넷이 안 됩니다. 모델은 셀룰러 데이터로 접근해야 합니다.

**키보드 제한.** 텍스트 입력은 ASCII만 가능합니다. 가로 모드 앱은 아직 지원되지 않습니다: 좌표 매핑과 보정이 현재 세로 모드를 전제합니다.

**레거시 버전.** 현재 버전은 자급자족형(iPhone + 보드)입니다. 이전 버전은 Mac 또는 Linux 컴퓨터에서 UxPlay와 Python 서버를 실행해야 했으며, 태그 `v0.1.0`과 `legacy` 브랜치에 보존되어 있습니다.

**라이선스.** MIT 라이선스이지만, `hardware/hid_bridge/src/airplay/`의 AirPlay 수신기 코드는 UxPlay에서 포팅된 것으로 GPL-3.0입니다. 이를 링크하는 펌웨어 바이너리는 따라서 GPL-3.0으로 배포됩니다.

**성숙도.** 저장소는 주로 C(펌웨어)와 Swift(iOS 앱)로 작성되었으며, 이 글 작성 시점에 3,564개의 스타가 있습니다. CI가 활성 상태입니다. 로드맵에는 가로 모드 지원, 비ASCII 입력, 멀티 액션 단계, 큐레이션된 모델 호환성 목록이 남아 있습니다.

**책임 있는 사용 관련.** README에는 이렇게 적혀 있습니다: 소유하거나 사용 권한이 있는 기기와 계정만 자동화하고, 관련 앱의 이용약관을 준수하고, 정지 버튼을 가까이 두라고 합니다.

## 왜 중요한가

대부분의 "computer use" 에이전트 데모는 데스크톱 브라우저나 Android를 대상으로 합니다 (접근성 API가 더 개방적이므로). iOS는 탈옥하거나 개발자 도구로 Mac에 연결하지 않으면 계측(instrumentation)이 어려웠습니다. 이 프로젝트는 하드웨어 계층에서 접근해서 소프트웨어 제약을 완전히 우회합니다: AirPlay와 USB HID는 특별한 권한이 필요 없는 표준 iOS 기능입니다. **제 견해로는, 이것이 현재 iOS computer-use 에이전트로 가는 가장 실용적인 경로입니다: 대역폭과 해상도를 대가로 런타임에 Apple 개발자 도구 의존성을 완전히 제거하는데, 이는 많은 에이전트 연구자가 수용할 트레이드오프입니다.**

README의 관련 프로젝트 표가 유용한 맥락을 제공합니다: VersaiOS는 컴퓨터가 필요하고, actell은 Developer Mode가 필요하고, AidenAI는 HDMI 캡처로 주로 Android를 대상으로 하고, boboabw/phone-agent는 가장 가까운 접근법이지만 AirPlay "눈"이 없습니다. WebDriverAgent 기반 도구인 mobile-mcp과 Midscene은 Mac과 코드 서명이 필요합니다.
